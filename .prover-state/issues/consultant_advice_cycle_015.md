### Mathlib infrastructure check for `def:310A` and `thm:301A`

Both targets need a notion of *rooted tree* with a vertex set and a
root. Mathlib has `Mathlib/Combinatorics/SimpleGraph/Tree/Basic.lean`
(a simple-graph-based tree predicate) but **no** general rooted-tree
inductive type that natively supports the recursion needed for
elementary differentials (which is "rooted tree = a multiset of
rooted trees, attached to a fresh root"). The cleanest approach for
the worker:

1. **Define a custom `RootedTree` inductive type** in
   `OpenMath/Chapter3/Section310.lean`:
   ```lean
   inductive RootedTree : Type
     | mk : Multiset RootedTree → RootedTree
   ```
   (or `List` instead of `Multiset` if the order is irrelevant — Butcher
   uses unordered children; `Multiset` is the right primitive). Note
   the well-foundedness check; Lean 4 will accept this with
   `Multiset` because of the strict-positivity-via-WellFounded
   handling, but it is worth verifying with a `#check` early.
2. Define `order : RootedTree → ℕ` (number of vertices) recursively.
3. Define the elementary differential `F[t](f) : ℝ^N → ℝ^N` for
   `t : RootedTree` recursively as in Butcher's §310. The recursive
   case requires the `f`-derivatives, for which Mathlib's
   `iteratedFDeriv ℝ k f` is the relevant primitive.
4. Worker should NOT attempt to prove all of §301A in one cycle if
   the rooted-tree infrastructure takes most of the cycle. Plan to
   write the inductive type, the order function, and the
   elementary-differential definition in cycle 016, and prove
   `thm:301A` in cycle 017.

The elementary differential `F` requires a smooth `f : ℝ^N → ℝ^N`;
the right Mathlib typeclass is `[ContDiff ℝ ⊤ f]` or `[ContDiff ℝ k f]`
for `k ≥ order(t)`. Verify with `lean_local_search "ContDiff"`.
